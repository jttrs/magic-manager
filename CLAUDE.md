# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`magic-manager` (`mm`) is a local-first MTG collection / set / wishlist / deck manager. Python 3.12, dependencies managed by `uv`, single-file SQLite store. No web service, no cloud — every command operates on `db/magic_manager.db`.

## Core engineering rules

These are standing rules for this repo — follow them without being reminded:

1. **Thin skill wrappers over deterministic scripts.** A user-facing skill / slash-command is a *relay*, not a place for logic. The real work lives in a deterministic `scripts/*.py` (or a `src/magic_manager/*` module it calls) that is the single source of truth; the skill invokes it and relays the output. No business logic, no arithmetic, no valuation math in skill prose. When network I/O is unavoidable (e.g. fetching a URL), do it on the Claude side of the skill and feed the script normalized, offline inputs. See `sealed-value`, `construct-value`, `review-earmarked-products` as the reference shape.
2. **Don't violate DRY.** Reuse existing engines and helpers instead of copying logic. New valuation reuses `sealed` / `construct` / `sets.card_price_map`; market-provider assembly reuses `sealed.make_market_provider`; artifact/slug writing follows the existing `scripts/*_value.py` helpers. If shared logic lives in a one-off home, **lift it into a shared home** (a module function, `util`, etc.) rather than duplicating it — a refactor that changes no behavior is preferable to a copy.
3. **Database changes follow the `db-upgrade` skill — no exceptions.** Any new `db.MIGRATIONS` entry, schema change, or one-off backfill: load `.claude/skills/db-upgrade/SKILL.md` and follow part A on the feature branch (additive migration, backfill as idempotent code registered in `scripts/post_merge_upgrade.py`, tests, and the two rehearsals — `scripts/rehearse_migration.py` + `post_merge_upgrade.py --db <pre-vN snapshot>` — with their verdicts in the PR). After merge, part B upgrades the owner's real DB (rehearse on a copy → owner OK → `--apply` → audits). Never copy a worktree DB over the real one.

## Running the CLI

The `mm` CLI is a `uv` project script (`pyproject.toml` → `mm = "magic_manager.cli:app"`); it is **not** on `PATH`. **Always invoke it as `uv run mm …`** — bare `mm …` will fail with `mm not found`. Skip the `which mm` / bare-`mm --help` probe; go straight to `uv run mm --help` or the specific subcommand.

Top-level subcommand groups (each `--help` lists its own subcommands):

```
uv run mm set …          # sync sets, is-synced, build/ingest inventory checklists, jumpstart-list, precon-list
uv run mm inventory …    # show / value / add / remove / import (V2 fact table)
uv run mm wishlist …     # categories of cards I want
uv run mm deck …         # decks (composition independent of ownership), combos <slug> (Commander Spellbook: in the deck / one card away), import-precon, import-deck (moxfield/archidekt/mtggoldfish/manabox/scryfall; re-pull deduped, --force replaces), push-moxfield
uv run mm query …        # selector queries: show, value, top, total, multiples, stats, url, xlsx, missing-set, card-diff
uv run mm checklists …   # inspect files in checklists/ (alias: `mm input …`)
uv run mm mtgjson …      # MTGJSON precon/set lookups (cached)
uv run mm db …           # snapshot, snapshots, restore, integrity, unlock (clear stale -wal/-shm)
uv run mm audit …        # deck-inventory + ingest-ledger + provenance consistency checks (--fix deletes orphan decks)
uv run mm intake <set>   # scan-loop REPL for fast bulk entry
uv run mm export …       # paste-ready blocks for moxfield/manapool/tcgplayer/cardkingdom/archidekt/plain/scryfall-json
uv run mm scryfall <q>   # ad-hoc Scryfall search via the rate-limited wrapper; `mm scryfall tags sync [--refresh]|show <card>` = Scryfall Tagger cache (V28)
uv run mm earmark …      # watchlist of sealed products across storefronts (add/list/rm-link/rm-product)
uv run mm analytics …    # self-hosted product analytics: summary, query/sql <saved query>, trace <ref>, prune, consent, forget, catalog (docs/analytics.md)
uv run mm serve          # web app: FastAPI JSON API + job runner (SSE) + built SPA from web/dist (see § Web app)
uv run mm edhrec …       # EDHREC community signal: commander (top cards for a commander) / card (top commanders running a card) / rankings (commanders|cards|salt, filterable by --color/--tag/--set) / compare (two commanders' recommended cards: Only-A/Both/Only-B + image-first HTML gallery) / sync (single card, OR bulk cache-warm via --selector/--family + --type)
```

There is a pytest suite under `tests/` (`uv run pytest`); fixtures use the
`MAGIC_MANAGER_DB` env override for a throwaway DB and monkeypatch the
`scryfall`/`mtgjson` wrappers so the suite is fully offline.

There is a pytest suite (`uv run pytest`, dev-dep in `pyproject.toml`); no linter config and no build step beyond `uv_build`. `uv sync` installs deps.

## Architecture (the parts that need cross-file reading)

### Selector grammar — the central abstraction

`src/magic_manager/selectors.py` defines a small DSL that nearly every read-side command (`query show/value/url/xlsx/missing-set`, `export`) parses and materializes into `(printing, finish, qty)` rows:

```
SELECTOR ::= TERM (' ' MODIFIER)*
TERM     ::= inventory | wishlist[:CATEGORY] | deck:SLUG
           | set:CODE[+related] | cards:SCRYFALL_QUERY | scryfall:SCRYFALL_QUERY
MODIFIER ::= missing[:nonfoil|foil|either] | owned | available
           | qty{>=,<=,=}N | finish={foil,nonfoil} | rarity=…
           | cn{>=,<=}N | value{>=,<=}N | scryfall:Q | treatment=…
```

When adding a query-shaped feature, prefer a new modifier/term over a one-off command — the rest of the read pipeline (sorting, exports, URL chunking, missing-set unions) gets it for free.

### Set families and the "missing from <set>" pipeline

A Magic "set" is rarely one Scryfall code. `sets_mod.resolve(name_or_code)` returns the parent + every set whose `parent_set_code` traces back to it (e.g. `fin` resolves to `fin` plus 8 siblings). The `set:CODE+related` term and `mm query missing-set <CODE>` build on this.

`mm query missing-set` is a flagship workflow (also exposed as the `missing-from-set` skill). It unions three printing-level sub-selectors (rare-regular, mythic-regular, treatment-class) and emits four artifacts: Scryfall URL chunks (chat output), an XLSX checklist (`output/missing-set/checklists/`) + ManaPool bulk-add `.txt` + TCGplayer Mass Entry `.txt` (`output/missing-set/buy-lists/`). Per-family configuration lives in `config/families.toml` (the `[dupe_foil]` / `[[unobtainable.<anchor>.rules]]` / `[[scenes.<anchor>]]` tables, loaded by `magic_manager.config` and exposed as `selectors.FAMILY_*`) — when supporting a new family, add its entry there first.

### Inventory checklists — generate → fill → ingest → archive

`checklists/` (formerly `input/`, both names work — `INPUT_DIR` is an alias) holds active XLSX/MD checklists awaiting ingest. The lifecycle is:

1. `mm set master-list <set>` writes `checklists/<slug>[-slice]-<mode>-checklist.xlsx`. Mode is `add` (blank cells, additive ingest) or `modify` (cells prefilled from current inventory, replace ingest); the mode token is in the filename, in a hidden `_meta` sheet, and restated in a visible **README banner sheet** (green for add, red for modify) — see `_add_mode_banner_sheet`.
2. User edits qty cells in Excel/Numbers (or any text editor for `--format md`).
3. `mm set ingest <set>` (or `--path <file>`) reads `_meta.mode` to pick semantics. **`modify` is non-destructive by default:** it SETS each in-partition row to its cell value (a signed change vs current — editing 3→5 nets +2, 3→1 nets −2, 0 zeroes that row), but does NOT auto-zero in-partition rows absent from the file. Zeroing absent rows (the old full-audit behavior) is opt-in: `ingest_inventory_from_xlsx(zero_untouched=…)`, surfaced as an interactive prompt (default No) or the `--zero-untouched/--no-zero-untouched` flag (`--json`/non-interactive callers default to No). Then it writes to `inventory`, archives under `checklists/processed/<…>-<timestamp>.xlsx`, and appends to `ingest_log`. Files are SHA-256-fingerprinted; re-ingesting the same file is refused without `--force`.

**Web checklist (same semantics, no file).** Collection's *Count cards* mode edits counts inline and saves through `sets.apply_counts(changes, label=)` (`CountChange(scryfall_id, finish, qty, expected)`): ONE `checklist` ingest event (label `web:checklist · <families>`, mode `replace`) that SETS each listed row and never touches others. All-or-nothing validation first — unknown printing (`LookupError`), bad finish/qty/duplicate (`ValueError`), `expected` ≠ current (`StaleCounts`), below copies pledged to built decks (`BelowPledged`). The per-row write `sets._write_count` (→ `inventory.inventory_set` + signed ledger delta) is shared with `ingest_inventory_from_xlsx`. API: `POST /api/collection/checklist` (`api.collection.save_checklist`, write-guarded → undo snapshot first; 409 stale with structured detail `{message, stale:[{scryfall_id, finish, expected, current}]}` (`StaleCounts.rows`, so the editor rebases + flags exactly those cells), 409 pledged, 404 unknown, 422 invalid).

There can be only one active checklist per slug+slice+format at a time (collision exits with `EXIT_UNPROCESSED_INTAKE = 3`).

**Deck checklists (precon + jumpstart).** A *precon* (preconstructed product) is the base concept; a *Jumpstart pack* is one species of it. `mm set precon-list` writes a **global, all-sets catalog** — one row per physical product (Commander Deck, Box Set, Planeswalker Deck, …) across every set, because there are only a handful of precons per set (a per-set file would be pointless). `mm set jumpstart-list <set>` is the Jumpstart-specific, per-set sibling. Both declare `kind` (`precon`|`jumpstart`) in a hidden `_meta` sheet, and `mm set ingest` dispatches on it (dispatch is hoisted to the top of `set_ingest` because the global precon catalog carries no `anchor_code` for the inventory anchor-resolution path). The CLI consumer is `_ingest_deck_checklist`, parameterized by kind.

**Add-mode deck checklists (jumpstart + precon `add`) use a single `acquired_qty`.** Both carry ONE fill column, `acquired_qty` (`[A:n]` in markdown) = copies acquired; ingest routes them to `_apply_acquired_checklist` (`sets.ingest_deck_checklist_from_path` dispatches: jumpstart always, precon when `_meta.mode == "add"`), which SPLITS the count deterministically so the user never pre-declares states: **products with no real decklist** (Starter Collection, Scene Box — auto-detected via name / card_count>150) → all `deconstructed`; **buildable & net-new** (`precon_unit_counts_for(fileName)[0] == 0`) → 1st copy `built` (recipe + `deck_assign_from_composition`) + rest `deconstructed`; **buildable & already own a built copy** → all `deconstructed`. Every copy — including jumpstart — becomes a tracked `decks` row via the shared `_build_precon_copies` helper (distinct `-2`/`-3` slugs, `pack:<theme>-<code>` for jumpstart / name-derived for precon), so built vs deconstructed counts stay derivable and there is **no silent "deck slug already exists" skip** — a redundant copy is a tracked deconstructed row. The shared parser (`JumpstartRow`) accepts the add-mode `acquired_qty`/`[A:n]` AND the modify-mode `constructed_qty` + `deconstructed_qty` / `[C:c D:d]`.

*Precon* tracks decks AS UNITS, with **the `decks` table as the single source of truth** — there is no separate ledger. Two columns make counts *derivable* so they can't drift: `decks.source_precon_file_name` (V10, the MTGJSON fileName join key) and `decks.precon_state` (V11, a 2-value model): **built** (assembled deck, cards pledged) or **deconstructed** (a deck torn down for parts — recipe kept, cards loose). Counts are `decks.precon_unit_counts[_for]()` → `(built, deconstructed)`, each a `GROUP BY precon_state`. `import_precon(..., precon_state=…)` stamps the fileName + state on the row it creates (a non-`built` state leaves cards loose/unpledged); the jumpstart engine still uses `deconstruct=True` with no `precon_state` for its rowless loose-packs path. `mtgjson.default_precon_state(fileName)` picks the ingest default — **deconstructed** for products with no real decklist (name in `POOL_NAME_PATTERNS`, a Scene Box's component decks, or a single deck with card_count > `POOL_CARD_COUNT_THRESHOLD`=150), else **built**; a user can flip a pool-shaped product to `built` manually via `mm deck add-precon -c` when they keep a copy intact. (The V7 `precon_ledger` was dropped in V10; the V11 migration backfills `precon_state` from `is_deconstructed` — the old column is left as a deprecated dead column.) The checklist has two flavors via `--mode`/`_meta.mode`. **`add`** (default): a single blank `acquired_qty` column (`[A:n]`); ingest routes to `_apply_acquired_checklist` (see the add-mode paragraph above) which SPLITS the count into built/deconstructed automatically. **`modify`**: two per-state columns prefilled from the live deck counts via `_build_precon_rows(prepopulate_from_counts=True)`; ingest runs through `_apply_precon_checklist` and applies the SIGNED DELTA — each positive delta in the constructed/deconstructed columns creates that many deck rows in the matching state (distinct slugs `<slug>`, `<slug>-2`, … via the shared `_build_precon_copies`/`_count_precon_deck_copies`); **any negative delta is NOT applied** — removing a copy is an explicit `mm deck delete <slug>` (the derived count updates automatically), so the checklist emits a per-row warning rather than deleting decks from a spreadsheet edit. (`mm deck add-precon`'s `-c`/`-d` flags also drive `_apply_precon_checklist(mode="add")` directly — that's the explicit-per-state caller.) Files are `precons-<mode>-checklist.xlsx`; add mode has one `acquired_qty` fill column, modify mode has two (`constructed_qty`/`deconstructed_qty`); MD uses `[A:n]` (add) or `[C:c D:d]` (modify), and both carry the same README banner (`_add_precon_banner_sheet`, add-mode text explains the split). `mm deck ls` shows a `state` column (`built`/`decon`); `mm deck add-precon -c/-d` and `import-precon --state` set it, auto-defaulting via `default_precon_state`. **Scope + value:** `precon-list` defaults to the constructed-deck product a collector tracks — `mtgjson.PRECON_MODERN_TYPES` (~680 rows: Commander/Box/Duel/Planeswalker/Starter/Welcome/Intro/Challenger/Guild/Brawl/Clash/Game Night/Archenemy/Planechase). That frozenset is the single knob for "what counts as a precon"; when a product line is reported missing, add its exact MTGJSON `type` string there. `--type X` narrows to one, `--all-physical` opens to every physical product (~1500 rows, incl. Deck Builder's Toolkit / Sample Deck / Welcome Booster / Shandalar / World Championship). Generation does NOT sync by default (an all-sets catalog can't sync all of Magic), so `usd_total` is best-effort — blank for sets not yet in the local `cards` table; ingest self-syncs each filled precon's sets (via `import_precon`'s sync-before-use), which also covers cross-set cards (e.g. a FIC deck's FIN reprints). Pass `--sync-all` to sync every referenced set (~180 for the default scope) up front so all totals populate in one run — `_build_precon_rows(sync_all=True)` does a pre-pass collecting each deck's `setCode`s, then `sets.unsynced_set_codes()` filters to the not-yet-local ones and `sync()` batches them (≤60 codes/query to stay under Scryfall's URL limit). **Collector's Edition** variants are a premium product the collection doesn't track — excluded via `mtgjson._is_collector_edition` (catches both the modern `… Collector's Edition` twins and the 1993 `Collectors' Edition` box sets) unless `--include-collector`. Digital (`MTGO …`), Jumpstart (its own command), and Secret Lair Drop (the `bulk-add` skill) types are never listed by `precon-list`.

### Database

SQLite at `db/magic_manager.db`, with `-wal`/`-shm` siblings colocated. Snapshots go to `db/bak/`, files displaced by `db restore` go to `db/replaced/`. Schema is created on first connect; subsequent versions add to the `MIGRATIONS` list and bump `CURRENT_VERSION` in `db.py`.

Set the `MAGIC_MANAGER_DB` env var to a file path to redirect the entire DB (used by `scripts/rehearse_migration.py` and any future tests).

**Price freshness.** `cards.prices_updated_at` stores the **fetch time** (when `mm set sync` last pulled that card's price), NOT the card's release date — `sets.sync` stamps one timestamp per run. Prices older than `sets.STALE_AFTER_DAYS` (**7 days**) are "stale". **Price commands are local-first by default**: they read prices from the local `cards` table and fetch over the network only to fill genuinely MISSING sets; stale (>7d) sets are left as-is and WARNED about, re-synced only with the explicit opt-in `--refresh` flag. Two DRY seams carry this, both local-first by default: `sets.priced_map` (id-keyed — `{scryfall_id: {usd, usd_foil, prices_updated_at}}`, used by `card_diff`/`set_status`/the HTML gallery) and `sets.ensure_priced` (set-code-keyed — plan = `sets.plan_sync` → `unsynced_set_codes` ∪ `stale_set_codes`, used by the value scripts `sealed_value.py`/`construct_value.py`/`review_earmarks.py`/`edhrec_report.py`). `--no-refresh` is kept only as a hidden, deprecated no-op alias for muscle memory. Every report prints a `Prices fetched: <date>` footer, and `mm set is-synced` shows each code's newest price date + a `(stale)` mark. `sets.card_price_map` returns `prices_updated_at` so callers can surface the basis. **Documented exception:** a handful of inherently cross-set/market commands are live by nature regardless of this convention — `card_floor_report.py` (anywhere-scope), `foil_price_diff.py`, `manapool_price_check.py` — these carry `--refresh` only for CLI surface consistency; it's a documented no-op.

V2 fact tables: `cards`, `inventory`, `wishlist_entries`, `decks` (with V10 `source_precon_file_name` + V11 `precon_state` built/deconstructed — precon unit counts derive from these; the V10 `is_deconstructed` column was dropped in V19; V22 `author` records the import source's deck creator — Moxfield/Archidekt — NULL for hand-built/precon/MTGGoldfish, stamped only at creation; V25 `source`+`source_deck_id` record the external builder + its native deck id an imported deck came from — the key `decksource.import_deck` dedups a re-pull against, so re-importing the same deck is refused (`mm deck import-deck` exits 3) unless `--force`, which REPLACES the deck's cards via `decks.deck_replace_cards` instead of the default create-or-append summing; NULL for hand-built/precon/pre-V25 decks), `deck_cards`, `ingest_events` + `inventory_events` (V19 provenance ledger — see below), `set_targets`. (The V7 `precon_ledger` was replaced by those derived counts and dropped in V10.) Pre-V2 used a single conflated `list_rows` table; see `docs/pre-v2-inventory-snapshot.md` for the migration baseline.

**Provenance ledger (V19) — inventory is a rebuildable cache over an append-only ledger.** The star schema roots ownership in ground truth: `inventory_events` (append-only, one SIGNED `delta` per `(ingest_id, scryfall_id, finish)`) is the fact table, and **`inventory.quantity` is the deterministic projection `SUM(delta)`** — inventory is a materialized cache, not the source of truth. `ingest_events` is the dimension: ONE row per ingest INSTANCE, tagged with a `method` ∈ {`checklist`, `precon`, `intake`, `adhoc`, `import-block`, `deck-assign`, `deck-unassign`, `migration-backfill`, `unattributed-backfill`}. This **subsumed the old `ingest_log`** (V19 copies its 247 rows forward, deriving `method` from the label prefix, then drops it). Every inventory write path routes through the ONE shared seam in `ingest.py` (`open_ingest_event` / `create_event` + `record_delta`, borrow-or-open like `db.transaction`) so the ledger append and the inventory mutation land in the SAME transaction — the log can no longer gap or drift (the pre-V19 `ingest_log` only covered 4 of ~8 write paths). `ingest.rebuild_inventory_from_ledger` re-derives inventory from the ledger; `ingest.reconcile_inventory_ledger` proves `inventory == SUM(delta)`. Standing guards: **`mm audit ingest-ledger`** (exits 1 on drift; `--rebuild` repairs) and **`mm audit provenance`** (per-method copy breakdown + the `unattributed-backfill` "provenance unknown" bucket). The one-off `scripts/backfill_provenance.py` reconstructed the ledger for the existing DB (precon decklists + archived checklists attributed, capped to current inventory; residual → the unattributed bucket so the sum is exact). `ingest_events`/`inventory_events` are **precious** (irreplaceable — adhoc/intake provenance lives nowhere else); `scripts/rehearse_migration.py` protects them and validates the V19 subsume.

**Pool true-up (`mm deck trueup` / `scripts/trueup_pools.py` / `trueup-pools` skill / web Collection → *Find products in your cards*).** Engine `magic_manager.trueup` (`plan(..., progress=, only=)` returns the result dict; the script and `mm deck product-coverage` are thin CLI drivers; `api.trueup` wraps it as the `trueup.scan` / `trueup.apply` jobs, apply re-checking exactly the reviewed list before writing). Shrinks the `unattributed-backfill` bucket by attributing LOOSE cards to the products they came from (scene boxes, precon/jumpstart decks, card pools, complete Secret Lair drops). Matches FREE (unpledged) inventory against product recipes (`decks.precon_recipe_needs` from `mtgjson.deck`; `sld.collect_drop_ids` for SLD CN-sets); a product is **claimed only on FULL coverage**, contested loose cards (Σ demand > free) are **reported not auto-resolved** (`--pick` to choose). **`mm deck product-coverage`** (alias `mm deck trueup`; skill `trueup-pools`; script `scripts/trueup_pools.py`) is the product-grain of the star schema: it imputes which deterministic-content products (precon / jumpstart / scene box / card pool / complete Secret Lair drop) the user's loose cards came from — a product-level "what have I bought / what should I buy" view. **Coverage is measured against the RE-ATTRIBUTABLE backfill balance** — per-`(sid,finish)` copies still held by any best-effort backfill event (`ingest_events.status='backfill'`: the `unattributed-backfill` bucket PLUS the generic `backfill:precon` / `backfill:checklist` reconstructions the V19 backfill created). NOT free inventory, and NOT just the unattributed bucket (matching only that starved the pass — 36k of 38.5k copies were locked in the generic precon/checklist buckets, so scene boxes and owned jumpstart-(1)s looked absent). Real post-V19 ingests (`status!='backfill'`) are NEVER re-attributable — genuine provenance is protected. **One physical copy backs at most one product** (supply is consumed as products claim it); overlap cases self-correct. This replaced a rejected "not-owned" flag model (V20 `excluded_products`, dropped in V21) — negative assertions go stale; balance-accounting doesn't.

**Contest resolution = priority, not manual.** When full-coverage products share a card the balance can't cover for all, the allocator (`_partition_ready_conflicts`) awards each shared card to the highest-priority claimant, consuming it so losers drop to NOT-COVERED. Priority is `config/product_priority.toml` (loaded via `tomllib`, baked-in defaults so it works with no file): a product-`type` → tier map where **Bundle Land Pack sits LOW** (basic-land filler shouldn't out-compete a real product for a shared basic) and jumpstart/precon/box/pool/SLD sit high; same-tier ties break by **lower version number** (the `(1)` beats `(2)` quirk), then release, then fileName. `--pick <fileName>` forces a product to the front (user override beats priority). Full coverage only; near-complete SLD (≥ `--sld-partial-threshold`) is advisory.

Dry-run (read-only report) by default; **review the OWNED list, then apply**. `--apply` registers each covered product as a `deconstructed` deck row via `decks.register_precon_from_loose` (the deconstructed sibling of `construct_precon_from_loose` — `import_precon(add_inventory=False, precon_state="deconstructed")`, no inventory/pledge write) AND records the product-grain acquisition as a new `precon` event, moving the exact card copies off the backfill buckets onto it (drawn unattributed→precon→checklist, capped per bucket, so `inventory == SUM(delta)` holds; linked by `ingest_id`). `--refute <fileName>` drops a product you did NOT buy from candidates (its cards stay available for a legitimate claimant); `--pick <fileName>` forces a product to win a contested card. Products imputed at ONE copy each — never multiplied from card quantities (redundant copies are tracked explicitly via add-precon/import-precon). Complete **Secret Lair drops** fold in as ONE product per logical drop. Modes: `--from-unattributed` (default = sets with re-attributable backfill balance), `<set/product>`, `--all`.

**Release dates (V27).** `cards.released_at` is the per-printing release date (projected from Scryfall on every sync; a re-sync without a date keeps the existing one). Pre-V27 rows are filled once from set-level dates by `uv run mm set backfill-dates` (`sets.backfill_released_at`, one cached `/sets` call, never overwrites). It powers `sets.standard_printing_by_oracle` — the oracle-grain *display-printing* sibling of `lowest_price_by_oracle` (oldest plain-frame, nonfoil-available, non-reskin, non-promo, physical printing; falls back to a treated one only when no standard printing exists locally), used by `edhrec.compare_commanders` for image/link fields.

**Scryfall Tagger oracle tags (V28).** `scryfall_tags` (one row per Tagger tag, keyed on its UUID — slugs/labels get renamed — with `parent_ids`/`child_ids` JSON hierarchy) + `card_oracle_tags` (`oracle_id`, `tag_id`, `weight` ∈ very_strong/strong/median/weak) are a REBUILDABLE cache (not precious) over Scryfall's OFFICIAL `oracle_tags` bulk file (`GET /bulk-data` → `data.scryfall.io`; never the tagger site/GraphQL). `scryfall_tags.sync(refresh=)` fetches via `scryfall.bulk_file` → `scryfall.sh bulk oracle_tags` (daily file, 24h listing cache, prints the cached local path) and fully re-derives both tables; it skips the rewrite when the same daily file is already loaded (`settings['scryfall_tags.source']`). Curated **function roots** live in `config/function_tags.toml` (optional, baked-in defaults in `config.function_tags`; a test keeps them in sync): Ramp, Card draw (`draw`), Removal, Board wipe (`sweeper`), Counterspell, Tutor, Recursion, Protection, Token maker (`repeatable-token-generator` + `multiple-bodies`), Sac outlet, Lifegain, Evasion (`gives-evasion`, not the keyword-ish `evasion`). `roll_up` maps cards to roots through the hierarchy (edges from both `child_ids` and inverse `parent_ids`); `card_summaries(oids)` is the ONE batched lookup (functions + top `preview_limit` tags, strongest weight first, functional tags first, `preview_exclude` meta subtrees dropped). `edhrec.compare_commanders` calls it once → `CompareCard.functions`/`oracle_tags` (named `oracle_tags` because `tags` already holds EDHREC list tags). Surfaces: `mm scryfall tags sync|show`, the `scryfall.sync_tags` JobSpec, the web Commanders **Group by → Function**, and the Collection **Function** filter (`api.collection.family_view` adds `functions` per card + the root list via the same one batched lookup).

**After pulling DB changes onto a real DB, follow the `db-upgrade` skill (part B): `uv run python scripts/post_merge_upgrade.py`** (rehearses on a copy; `--apply` snapshots then upgrades the live DB). It applies V27–V30 and their backfills (`set backfill-dates`, `scryfall tags sync` (oracle + art), `deck backfill-kinds`, `set backfill-illustrations`) and proves inventory, the ledger, wishlist, deck compositions/pledges/identity are byte-identical and the ledger still reconciles. A dev/worktree DB is never copied over the real one.

**Art tags (V30).** `cards.illustration_id` links printings to Scryfall artworks (projected on sync, COALESCE-kept; `mm set backfill-illustrations` fills old rows from the `default_cards` bulk). `scryfall_tags` holds both kinds (`type` = `oracle` | `illustration`); art taggings live in `illustration_art_tags(illustration_id, tag_id, weight)`. `scryfall_tags.sync_kinds()` / `mm scryfall tags sync [--kind]` refresh both; hierarchy queries are kind-filtered so art tags never reach Function grouping. `magic_manager.scryfall_art` is the engine (`printings_with_art(tag, oracle_ids=, owned_only=)` with tag roll-up, `art_tags_for_printings`, `art_tag_search`); `mm scryfall art <tag> [--cards|--deck] [--owned]`. Surfaced in the web deck editor's **Art** tab via `art_swap.py` (see the module map).

**Playable decks vs card pools (V29).** `decks.kind` ∈ {`deck`, `pool`} separates playable recipes from product card pools that ride the `decks` table for provenance. `mtgjson.precon_kind` is the ONE classifier (shares `default_precon_state`'s pool tests): pool = `Bundle Land Pack`, Scene Box / Starter Collection (name patterns or scene-box component), > `POOL_CARD_COUNT_THRESHOLD` cards, a `Secret Lair Drop` with < `sld_min_playable_cards` (40) playable cards, or anything with < `min_playable_cards` (20) — Archenemy scheme decks excepted; knobs in `config/precon.toml`. `import_precon` stamps it on write; `decks.kind_source` (`auto`|`user`) protects overrides: `mm deck set-kind <slug> deck|pool`. Pre-V29 rows are classified by `mm deck backfill-kinds` (idempotent, network-bound — run it once after pulling V29; `deck_view.deck_summaries` also runs it lazily if any precon row is unclassified, which makes that first call slow). The Deck Manager lists only `kind='deck'`, one row per recipe (precon copies grouped by `source_precon_file_name`, `built`/`loose` counts).

**Token tracking (V14).** The user collects tokens, so they ARE tracked — but never appear in "missing set" buy-lists (you don't buy tokens to complete a set). Three facts: (1) `cards.is_token` flags tokens/emblems/DFC-tokens (`db.py` projection keys on `layout ∈ {token, double_faced_token, emblem}`). (2) **Precon tokens ride the deck.** `import_precon` walks the MTGJSON `tokens` board (`_BOARD_KEY_TO_NAME` in `decks.py`) onto the V14 `'token'` `deck_cards.board` AND into inventory, and auto-syncs the token set (e.g. `ttmc`) since its `setCode` is collected in the same loop — so precon tokens are kept with the precon deck and count toward `deck_value`. (V14 added `'token'` to the `deck_cards.board` CHECK via a table rebuild; `decks.backfill_token_board()` is the idempotent one-off that moved pre-V14 tokens off `'main'`.) (3) **Missing-set hard-excludes tokens** at a single chokepoint in `missing.missing_printings` (an `is_token` filter over all sub-selectors — NOT the fragile rarity gate, since rare/mythic tokens exist). Loose tokens enter via `mm set master-list <fam> --include token` (checklist), ad-hoc `mm inventory add-card`/`mm intake`, or `mm set sync <fam> --with-tokens` (folds in the family's `set_type='token'` children so they're available without a manual `sync ttmc`).

### EDHREC community signal (V23)

EDHREC has **no official API**; its Next.js front-end fetches **name-keyed** JSON from `json.edhrec.com/pages/…` (the `/pages/` prefix is mandatory — the bare host 403s; there is no `api.edhrec.com`). The join key on EDHREC is a **sanitized card name** (no scryfall/oracle id anywhere), so integration = up-level a printing → oracle name → EDHREC slug → fetch → re-attach `oracle_id` on our side by resolving names against local `cards` (V13 `cards_oracle_idx`; lazy Scryfall by-name fill for gaps, upserted so metadata sticks). `edhrec.slugify` is the DRY slug rule (lowercase → strip `'`/`,` → non-alphanumerics to `-`; DFC uses the front face).

**Persistence is hybrid** (V23 tables, a REBUILDABLE cache — NOT precious): `edhrec_pages` is the raw-JSON snapshot (source of truth, one row per fetched page, so a later migration can normalize new metrics without re-fetching), and three normalized query tables are derived from it — `edhrec_commander_cards` (workflow A), `edhrec_card_commanders` (workflow B), `edhrec_rankings` (workflow C). Every sync upserts (idempotent). **V24** added `edhrec_rankings.filter` (part of the PK) to key filtered commander rankings distinctly: `''` (unfiltered), `color:<slug>`, `tag:<slug>`, `set:<anchor>`.

Four deterministic workflows, all in `edhrec.py` (client + engine) → `scripts/edhrec_report.py` (report math/formatting) → `mm edhrec` (thin CLI relay) → `edhrec-{commander,card,rankings,compare}` skills:
- **A** `mm edhrec commander "<card>"` — highest-inclusion cards when `<card>` is the commander (`container.json_dict.cardlists` recommendation lists; carries `synergy`).
- **B** `mm edhrec card "<card>"` — most common commanders running `<card>` in the 99 (card page's `topcommanders`/`newcommanders` lists; deck counts only, no synergy/lift).
- **C** `mm edhrec rankings <commanders|cards|salt>` — general rankings (`/pages/commanders/<tf>.json` has a real `rank`; `/pages/top/<tf>.json`; `/pages/top/salt.json` carries a `salt` score). Salt/cards pages carry no `rank` → derived from array position. **Filtered commander rankings** (V24, commander-scope only, MUTUALLY EXCLUSIVE): `--color` (WUBRG letters `wu`, guild/shard/wedge names `azorius`/`bant`, `mono-red`, `five-color`, `colorless` — mapped by `edhrec.color_filter_slug` / `_COLOR_SLUGS`, keyed on the frozenset of letters) → `commanders/<color-slug>[/<tf>]`; `--tag` (creature type OR theme — EDHREC serves BOTH from ONE `/tags/<slug>` namespace, so goblins and treasure are the same axis; **all-time only — a `tags/<slug>/<tf>` request 403s**) → read `topcommanders` (24) + `newcommanders`, deduped, NOT the "first non-empty" list; `--set` (family-expanded via `sets.resolve`, unions each code's `commanders(<code>)` list) → `sets/<code>`. **Filters do NOT stack** (EDHREC 403s `commanders/mono-red/goblins`) — one axis + optional timeframe. `edhrec._plan_rankings` resolves the fetch + explicit list-selection per axis; `sync_rankings(scope, timeframe, *, color, tag, set_family)` is the one seam. **Read-or-sync:** `ranking_key(...)` computes the stored identity OFFLINE (`RankingKey(scope, timeframe, filter)` — the same validation sync uses; set → `sets.resolve` anchor, tag/salt → `all`, set → `''`), `cached_rankings(key)` reads the newest batch (rows sharing `MAX(fetched_at)`, so entities that fell off the list drop out), `rankings(..., refresh=, progress=)` = cached else sync. `ranking_title(key)` is the one naming rule (`Top commanders · Mono-Red · past week`) shared by the CLI report and the web; `color_options()` lists the 32 identities; `RANKING_TIMEFRAMES` = week|month|year (EDHREC's `year` = past 2 years).
- **D** `mm edhrec compare "<A>" "<B>"` — compare two commanders' recommended cards. Reads EACH commander's FULL recommendation set (every `list_tag`, read-or-sync via `_commander_card_entries` → cached `edhrec_commander_cards` rows when the commander page is present, else `sync_commander`), dedupes per commander by `card_oracle_id` (fallback `card_slug`) keeping `list_tag`s as filterable TAGS, then partitions the UNION by card into **a_only / both / b_only** (`both` carries each side's inclusion % + a `delta` = `abs(a_pct − b_pct)`). `edhrec.compare_commanders(ref_a, ref_b) -> CompareResult` is the one seam (`CompareCard` dataclass); enrichment is ONE batched `sets.lowest_price_by_oracle` (type/MV/lowest-USD + the representative printing's `scryfall_id`/`image_uri`/`set`/`cn` — the fields that extension added for gallery tiles). Emits md (three bucket tables + a biggest-disagreement table) + JSON + XLSX + an **image-first HTML gallery** via the shared `magic_manager.gallery` renderer (sections = buckets, pool chips = category tags, per-tile badge = each commander's inclusion %, numeric sorts = inclusion/synergy/trend/delta). `scripts/edhrec_report.py`'s `_run_compare` is the driver.

**Bulk cache-warming (no report).** `mm edhrec sync` is overloaded: a single positional CARD warms one card (unchanged), OR bulk-warms a whole card universe via `--selector`/`-s` (any selector DSL string — `set:fin+related`, `cards:t:legendary e:msh`, `deck:<slug>`, `inventory`) or the `--family a,b,c` sugar (unions each `set:<code>+related`), optionally narrowed by `--type` (a case-insensitive `type_line` substring, e.g. `"legendary creature"`). This is DRY over the selector engine — `edhrec.names_from_selector(selector, *, card_type)` materializes → offline-filters → dedupes to oracle names (dropping **tokens** via `is_token` and **digital-only** cards via the canonical `selectors._is_digital_only`, which catches arena-stamped Alchemy originals that carry no `A-` prefix), and `edhrec.sync_bulk(names, *, resume, progress) -> BulkSyncResult` loops the per-card `sync_both` seam. **Resumable (per-eligibility)**: `resume=True` (default) resolves each name once (24h-cached) and skips it only when its EDHREC pages are FULLY cached — a card-only card needs just its `card` page, a commander-eligible card needs BOTH its `commander` and `card` pages (so an interrupted eligible card still completes) — via `edhrec._cached_slugs()`; `--no-resume` forces re-fetch. **Fail-soft with a bug/transient split**: expected `EdhrecError`/`ScryfallError` are tallied as retryable failures, while an unexpected exception (a changed-page-shape `AttributeError`, a `sqlite3` error) is tagged `BUG: <type>` so a deterministic code bug reads as a bug, not fetch noise (the loop still continues). Bad selectors exit cleanly (`SelectorParseError`/`LookupError` → exit 2), mirroring the read-side `_materialize_or_die`. No report artifacts — cache-warming only. Example: `mm edhrec sync --family tla,tmt,fin,spm,msh,ltr,hob,blb --type "legendary creature"`.

Reports enrich each entity with local metadata via **`sets.lowest_price_by_oracle`** (new — the oracle-grain sibling of `card_price_map`: `GROUP BY oracle_id, MIN(prices_usd)` for the cheapest USD across printings + type/mana-value/color-identity/rarity). Pricing is local-first by default (see § Price freshness) — cards from unsynced sets degrade gracefully to blank metadata unless the explicit `--refresh` opt-in is passed. Emit: markdown table to chat (Scryfall-hyperlinked) + JSON + XLSX under `output/edhrec/reports/` (the JSON doubles as the eventual web-app data contract). Access is the standard triad: `.claude/skills/edhrec-search/edhrec.sh` (rate-limited, 24h cache, 429 backoff) + `.claude/hooks/edhrec-guard.sh` (blocks ad-hoc curl to `json.edhrec.com`).

## Conventions

- The user is the only consumer of this codebase; back-compat shims (`INPUT_DIR` alias, `mm input …` typer alias) exist only as long as the user's muscle memory needs them. No need to add new ones for hypothetical future callers.
- Filename conventions encode intent for Finder/cmux (no `_meta` visible there): `<slug>-<slice>-<mode>-checklist.xlsx`, `<code>-jumpstart-checklist.xlsx`, `precons-checklist.xlsx` (global, all-sets), `missing-<code>-checklist-<ts>.xlsx`, `missing-<code>-{manapool,tcgplayer}-<ts>.txt`. Keep them stable — skills and slash commands grep for them.
- `output/<type>/<category>/` is for ephemeral generated artifacts, segmented by producer (`missing-set`, `missing-jumpstart`, `jumpstart-buildable`, `sealed-value`, `construct-value`, `cart-check`, `earmarks-review`, `query`) and purpose (`reports` / `buy-lists` / `checklists`). All writers go through the one seam `util.output_dir(type, category)` — never hardcode a path. The `cleanup-queries` skill prunes the tree (recursively). Don't put anything durable there. (The old flat `queries/` dir was fully migrated to this in the output-reorg; no back-compat.)
- `docs/` is reference, not always implemented — file headers say "Documented but not implemented as of V<N>" when the schema/design exists but the importer doesn't yet.
- **Branch merges go through a PR — never merge a feature branch straight into `main` locally.** When work on a branch is ready: push the branch, then open a PR with `gh pr create` (don't `git merge` into `main` yourself). The PR is the merge seam even for a solo repo — it gives a review surface and a clean history record. Commit/push only when the user asks (standard rule); when they ask to "merge", that means open/merge the PR, not a local `git merge`.

### Per-set knowledge (`docs/sets/`)

`docs/sets/<anchor>.md` is the durable memory doc for each set-family (LTR, FIN, SPM, TLA, TMT, …). Each follows the shape defined in `docs/sets/_TEMPLATE.md`: family map, treatments, chase variants, scenes/posters, unobtainable rules, PRM destinations, edge cases, code refs, product types. For **cross-family product-type archetypes** (Scene Box, Beginner Box, Jumpstart, Commander/Welcome deck, masterpiece sheet, Bundle, Secret Lair, Collector's Edition) — sourcing, MTGJSON mapping, handling — see `docs/product-types.md`; a per-family doc records only that family's product *specifics* and links there for the definitions. (`docs/product-types.md` explains the archetypes behind `mtgjson.PRECON_MODERN_TYPES`, the constant that drives `precon-list`.)

**Read before answering.** When the user asks a set-specific question or you're working on a set-specific command, `Read` `docs/sets/<anchor>.md` **before** answering. It captures peculiarities Scryfall metadata doesn't (chase variants, scene groupings, family-topology gotchas like MAR being a separately-rooted SPM bonus sheet). If no doc exists yet for the family, suggest running the `characterize-set` skill to bootstrap one.

**Update when you learn something new.** If a session surfaces a new per-set fact — a chase variant we hadn't catalogued, a scene grouping, an unusual `promo_types` behavior, a new PRM destination, a family-topology gotcha — add it to the appropriate section of `docs/sets/<anchor>.md` before ending the session. Keep entries dense and factual (every row of every table should be verifiable via `mm scryfall` or the survey script).

**Code + doc + config stay in sync.** `docs/sets/<anchor>.md` §8 "Code refs" points at a family's `config/families.toml` entries (`[dupe_foil]` / `[[unobtainable.<anchor>.rules]]` / `[[scenes.<anchor>]]`). If you add/remove a family's config, update the doc's §8 in the same commit — `tests/test_config_schema.py` enforces the config↔docs §8 sync as a standing CI guard (a configured family with no doc, or a doc §8 referencing absent config, fails the suite).
